## Confirmed findings

### 1. P2 — EMA's explicitly dated first meeting is missing

Source `instagram:post:3994807273716605662`, account `emaatucr`, says: September 29, 2–3 PM, HMNSS 2211, followed by weekly Tuesday meetings. It has no published event IDs and no corresponding live EMA listing.

The first model response invented December 11 as the recurring schedule's end. The validator correctly rejected that unsupported boundary. The retry removed the schedule but kept `kind=activity` with no occurrences, which was also correctly rejected.

The recovery guidance in `pipeline/content_assessment.py:540` directs an unbounded schedule toward empty occurrences. It misses the useful fallback when the first meeting is explicitly dated. An offline response containing only the September 29 meeting passes the existing validator. Publish that supported occurrence without inventing a quarter end. This source is cached with `retryable=false`, so an ordinary rerun will not recover it.

### 2. P2 — A map QR code becomes an RSVP requirement

[Riverside Art & Music Festival](https://www.instagram.com/p/DdmGK-vmof_/) is live as `ig_ucrtaps_p3991215763134136362`, with:

- `rsvp_required=true`
- `rsvp_url=https://maps.app.goo.gl/KpfeSoemNXCk5Wwg8`

The saved flyer QR destination is a Google Maps URL. `pipeline/instagram_rows.py:133` chooses a sole QR URL as the registration destination; line 156 treats any resulting URL as proof that RSVP is required. `pipeline/url_utils.py:38` checks URL shape and a few exclusions, but does not establish registration intent. Offline row mapping reproduces both incorrect values.

This event predates #49 but was written again during it. A directions URL should remain a directions link and should not establish an attendance requirement.

### 3. P2 — The art festival is categorized as career

The same festival row has `category=career`, despite advertising arts, live music, installations, and performances. Its caption mentions workshops. The category vocabulary in `pipeline/category_inference.py` lacks standalone art/music/festival concepts, so the incidental workshop score wins a tie against community text. Offline category inference and full row mapping both reproduce `career`.

This is a remaining activity-category coverage gap, distinct from the map/RSVP bug.

### 4. P2 — College Night displays an unsupported venue

[Chance Encounters: College Night](https://www.instagram.com/p/DdpwxymDFrW/), `ig_ucrarts_p3992937072452983510`, displays `UCR (implied by college lounge/UCR mention)` as its location. The saved September 24 assessment explicitly inferred this from a caption addressing students at UCR and other colleges. That text does not establish a venue.

The new reminder, source `instagram:post:3994869751280487508`, explicitly names **The Culver Center**. It was refused because “October 1 at 6” does not explicitly support 18:00 under the clock validator. The event already exists at October 1, 6–9 PM from its earlier source, so this is not a wholly missing College Night event.

The older inferred location still passes current validation: `pipeline/content_assessment.py:466` checks that a location citation exists, but does not check whether the venue is supported by that citation. Keep the clock safeguard; correct the venue through source review and strengthen location grounding. The new reminder refusal is also non-retryable.

### 5. P2 — A fundraiser slips through the fundraiser exclusion

[Dunk a Dove](https://www.instagram.com/p/Ddwoa68moFH/), newly published as `ig_epsilonsigmazetas_p3994870641338253639`, is labeled `student_event`. Its source advertises supporting a good cause and a second slide lists water balloon/bucket prices. The assessment itself describes a fundraising event.

The classifier only checks title and caption for literal fundraiser terms (`pipeline/classify.py:26`, `:278`). This caption uses “supporting a good cause,” so it misses the terms. The mapper discards the assessment's reasoning and publishes the activity. Full offline row mapping reproduces the result.

Under the current fundraiser exclusion, this is a false negative. Use explicit, contextual fundraiser evidence; broadly excluding every mention of a good cause would also suppress legitimate volunteering.

### 6. P2 — App CI fails on the same revision

[App CI run 36261219191](https://github.com/Highlander-Builders-Initiative/HighlanderHub/actions/runs/36261219191) fails with 177 passing tests and one failed test file:

`tests/event-query-boundaries.test.mjs:3` imports `registerHooks` from `node:module`, but CI runs Node 20.20.2. The log reports that the module does not export that name. `.github/workflows/ci.yml:31` selects Node 20.

Align the test's module-hook mechanism with the supported CI runtime, or deliberately update the runtime. This is separate from the successful Python ingestion run.
