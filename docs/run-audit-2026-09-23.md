## Confirmed problems

### 1. P2 — A board application deadline is suppressed as a fundraiser

[Reach Initiative post](https://www.instagram.com/p/Ddml2hGErzG/) `3992044593818549446` explicitly advertises board applications due October 1 at 11:59 PM. The semantic assessment correctly identifies a deadline. Nevertheless, the source has empty `event_ids` and no live listing.

`pipeline/classify.py:257` gives any fundraiser keyword in title/description precedence over the assessed kind. The job title **Fundraising Chair** triggers this rule, so `post_rows` discards the resulting fundraiser row. Offline replay returns `fundraiser`; replacing only that role label with “Finance Chair” returns `student_deadline`.

This is a false positive in the fundraising exclusion, not a model refusal or an admin deletion. Preserve the real fundraiser exclusion while distinguishing an advertised fundraising activity from a role or incidental mention. Review and republish this source after repair.

### 2. P2 — An explicit relative weekday deadline is wrongly rejected

[UCR Services R’Card post](https://www.instagram.com/p/Ddos-59pHOb/) `3992638906555462555`, posted Wednesday September 23 at 9:09 AM Pacific, instructs students to collect their cards by 4 PM **this Friday**. Both saved model attempts chose September 25 at 4 PM and cited the caption. Both were refused, and the source has no event IDs.

`pipeline/content_assessment.py:391` supports today, tonight, and tomorrow but no relative weekdays. Calling `_day_supported` with this source and September 25 returns false. This is a validator coverage defect. It should support a clearly qualified weekday relative to the Pacific publication date without accepting arbitrary bare weekdays or publication dates alone.

The refusal is cached as non-retryable. An ordinary scheduled run will not reconsider it after a code change without a targeted reassessment.

### 4. P2 — Publication recreates already-reconciled duplicates every cycle

The latest run's saved inputs reproduce **174 row proposals, 27 absent identities recreated, 3 canonical updates, and 27 duplicate removals**. Those numbers match the run log. Every recreated identity is subsequently mapped back to an existing canonical event.

Examples include repeated Block Party advertisements, Fall Reception posts, Taste of MESCafé, and the new McNair reminder. The two earlier runs likewise logged 26 removals each.

`pipeline/assessed_events.py:282` only skips identical negative/refused decisions. A positive cached assessment is remapped to its original post ID, even when `source_assessments.event_ids` now points at the canonical replacement. Publication upserts the original row; reconciliation then removes it again.

This produces unnecessary writes and exposes duplicates between the committed publication transaction and the later reconciliation transaction. A failure between those stages can leave them present until a later successful reconciliation. Fix durable handling of canonical replacements for unchanged positive decisions; do not simply skip every positive cache hit, since missing-row recovery and changed admin overrides still need to work.

### 5. P2 — Negated registration text becomes RSVP required

[Fall Involvement Fair](https://www.instagram.com/p/Ddon29KSW4b/) `3992616370000457243` says **“No registration required just show up!”**, but its live row has `rsvp_required=true` and no RSVP URL.

`pipeline/instagram_rows.py:113` searches `_RSVP_TERMS` without considering negation. The word “registration” alone makes the flag true. An offline check with just that sentence reproduces it.

The same heuristic treats an incidental “link in bio” as a registration requirement; the BAKU GP Discord stream is another example where the source establishes a viewing link, not required registration. Fix explicit negation and distinguish event access links from mandatory signup.

### 6. P2 — Keyword categories describe incidental text instead of the activity

The latest Joel Mejia Smith performance row `ig_kucr883fm_p3992721570257688767` has `category=career`. Its caption points readers to an interview, so the category scorer finds “interview”; standalone “performance” and “dance” do not match its arts concepts. The earlier post for the same performance is correctly categorized as arts.

The new **909DT Pre-Audition Workshop with Aamyah Davis** is also categorized career, although its caption explicitly describes a dance workshop. `pipeline/category_inference.py` treats workshop as a career keyword without activity context.

Both values reproduce from saved input. A repair should prioritize the advertised activity over an incidental interview, promotional sentence, or ambiguous workshop keyword.

### 7. P2 — A retrospective recap was published as an event

[GSBA Mount Rubidoux hike recap](https://www.instagram.com/p/DdmxQaiBtl9/) `3992094751989356925` says **“thank you for participating”** and prints September 21. The model's own explanation describes an event that took place, but classifies it as activity. A live September 21 all-day event was created on September 23.

The post was published September 22 at 3:08 PM Pacific. The generated all-day end is September 22 at midnight; the one-day stale-event grace in `pipeline/event_dates.py:352` therefore lets it through. Its classification still passes structural/date validation because the printed date is real.

This is a semantic recap false positive. It is already past, so the demonstrated impact is erroneous historical data rather than an upcoming-feed item. Do not remove the general grace period solely to compensate for this one semantic error.
